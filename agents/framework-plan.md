## 1. Goal

Upgrade the existing **pw-live-lab** challenges from JavaScript-style TypeScript (untyped `res.json()`, copied login/reset, loose names) into a **small, typed Playwright Test framework** that Omer can explain line by line in an interview: shared models, a generic `readJson<T>`, union literal statuses, `test.extend` fixtures, page objects, and the 19 challenges migrated into real specs.

**What this is not:** this is not a rewrite of the QA Co-Pilot Hub, and it is not a cucumber-js framework. The Hub's Framework Builder is only the coaching shell. The work happens in `pw-live-lab`. Claude Code may transcribe these tasks into `lib/frameworkTasks.ts`; Omer (with the Muallim) builds the framework himself.

**Privacy rule (hard):** no employer names, internal app names, codenames, internal field names or colleague names anywhere in the code, prompts, sample data, README or commit messages. The practice domain is the generic "Trade Desk Lite" order ticket app already in `practice-app-v2/`.

**Tonight vs later:** T01–T05 are the items worth rehearsing before a technical round (typed models, `readJson<T>`, union statuses, one `test.extend` fixture with `apiClient` and an authed page, and env config so credentials stay out of source). T06–T21 are the full framework and can wait.

## 2. Task shape

Each task has: **goal**, **files**, **checks** (auto = verified by the app; cmd = verified from terminal output/report; manual = Omer ticks it), and **hints** (revealed one at a time, never the full solution). Status starts at `todo`.

```ts
// shape in lib/frameworkTasks.ts
interface FrameworkTask {
  id: string;                 // 'T01'
  group: 'setup' | 'core' | 'ui' | 'api' | 'hybrid' | 'tooling' | 'ci' | 'advanced';
  title: string;
  goal: string;
  files: string[];
  checks: AcceptanceCheck[];  // { type: 'fileExists' | 'fileContains' | 'validJson' | 'command' | 'manual', ... }
  hints: string[];            // ordered, least to most specific
  concepts: string[];         // refresher topic names, for cross-links
}
type TaskStatus = 'todo' | 'in_progress' | 'review' | 'done';
```

When transcribing the table below, map the shorthand as follows:

- `auto: <file> exists` → `{ type: 'fileExists', path }`
- `auto: <file> contains …` → `{ type: 'fileContains', path, patterns, match: 'all' | 'any' }`
- `cmd: …` → `{ type: 'command', command, expect }` (add a `verify` regex when the output is stable)
- `manual: …` → `{ type: 'manual', label }`
- `group` / `concepts` are not table columns; use the suggested group in the notes under the table, and short concept tags from the title (e.g. `interfaces`, `generics`, `fixtures`).
